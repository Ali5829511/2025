## 🤔 متى يجب الدمج؟ متى يجب الترك؟

### ✅ يُنصح بالدمج في هذه الحالات:

1. **الميزة مكتملة**
   - ✅ الكود مكتوب ومختبر
   - ✅ مراجعة الكود تمت
   - ✅ لا توجد أخطاء معروفة
   - ✅ جاهز للإنتاج

2. **الفرع نشط ومحدث**
   - ✅ تم التحديث مؤخراً (أقل من شهر)
   - ✅ متزامن مع الفرع الرئيسي
   - ✅ لا توجد تضاربات كبيرة

3. **الفريق جاهز**
   - ✅ المطورون متاحون لحل التضاربات
   - ✅ وقت كافٍ للاختبار بعد الدمج
   - ✅ خطة نشر واضحة

### ⏸️ يُنصح بالانتظار في هذه الحالات:

1. **الكود غير جاهز**
   - ⏸️ لا يزال قيد التطوير
   - ⏸️ الاختبارات غير مكتملة
   - ⏸️ توجد أخطاء معروفة
   - ⏸️ يحتاج مراجعة إضافية

2. **تضاربات معقدة**
   - ⏸️ تضاربات كثيرة مع الفرع الرئيسي
   - ⏸️ تغييرات كبيرة في ملفات مشتركة
   - ⏸️ يحتاج دراسة وتخطيط

3. **التوقيت غير مناسب**
   - ⏸️ قبل إصدار مهم مباشرة
   - ⏸️ الفريق مشغول بأولويات أخرى
   - ⏸️ فترة إجازات أو عطل

### 🗑️ يجب حذف الفرع في هذه الحالات:

1. **بعد الدمج الناجح**
   - 🗑️ الفرع دُمج في الفرع الرئيسي
   - 🗑️ PR مغلق ومقبول
   - 🗑️ لا حاجة للرجوع للفرع

2. **الفرع قديم وغير نشط**
   - 🗑️ لم يُحدث منذ أكثر من 6 أشهر
   - 🗑️ الميزة ألغيت أو تم تنفيذها بطريقة أخرى
   - 🗑️ المطور ترك الفريق

3. **فرع تجريبي**
   - 🗑️ تم إنشاؤه للاختبار فقط
   - 🗑️ التجربة انتهت
   - 🗑️ لن يُستخدم في الإنتاج

## 🔧 خطوات عملية

### السيناريو 1: دمج فرع جديد (موصى به)

```bash
# 1. تحديث الفرع الرئيسي
git checkout main
git pull origin main

# 2. الانتقال إلى فرع الميزة
git checkout feature/new-feature

# 3. تحديث من الفرع الرئيسي
git merge main
# أو استخدم rebase للتاريخ الأنظف
# git rebase main

# 4. حل أي تضاربات
# راجع الملفات المتضاربة
git status
# بعد الحل
git add .
git commit -m "Resolve merge conflicts"

# 5. دفع التغييرات
git push origin feature/new-feature

# 6. فتح Pull Request على GitHub
# - اذهب إلى GitHub
# - اضغط "New Pull Request"
# - اختر feature/new-feature -> main
# - أضف وصف واضح
# - اطلب مراجعة من الفريق

# 7. بعد الموافقة والدمج
git checkout main
git pull origin main
git branch -d feature/new-feature
git push origin --delete feature/new-feature
```

### السيناريو 2: تنظيف الفروع القديمة (اختياري)

```bash
# 1. عرض جميع الفروع البعيدة
git branch -r

# 2. عرض الفروع المدموجة فقط
git branch -r --merged main

# 3. حذف فرع معين (بعد التأكد!)
git push origin --delete branch-name

# 4. تنظيف المراجع المحلية
git fetch --prune

# 5. عرض الفروع المحلية
git branch

# 6. حذف فرع محلي
git branch -d branch-name
# أو إجباري
git branch -D branch-name

# ⚠️ تحذيرات مهمة:
# - لا تحذف الفروع النشطة
# - لا تحذف الفروع التي لها PRs مفتوحة
# - تأكد من الدمج قبل الحذف
# - احتفظ بنسخة احتياطية إذا كنت غير متأكد
```

## 📚 استراتيجيات إدارة الفروع

### 1. Git Flow (للمشاريع الكبيرة)

```
main          ────●────●────●────●───→ الإنتاج
               ╱      ╱      ╱
develop    ───●──────●──────●─────→ التطوير
            ╱  ╲    ╱  ╲
feature/*  ●    ●  ●    ●  الميزات
```

**الفروع:**
- `main`: الإنتاج فقط
- `develop`: التطوير الرئيسي
- `feature/*`: ميزات جديدة
- `release/*`: الإصدارات
- `hotfix/*`: إصلاحات عاجلة

### 2. GitHub Flow (للمشاريع الصغيرة - موصى به)

```
main       ───●───────●───────●───→ الإنتاج
            ╱         ╱         ╱
feature   ●─────────●─────────●     الميزات
```

**البساطة:**
- فرع `main` واحد
- فروع `feature/*` للميزات
- دمج مباشر بعد المراجعة
- حذف الفرع بعد الدمج

### 3. Trunk-Based Development (للفرق السريعة)

```
main  ───●──●──●──●──●──●───→ دمج سريع
```

**السرعة:**
- دمج يومي في `main`
- فروع قصيرة الأمد (ساعات/أيام)
- اختبارات تلقائية
- نشر مستمر

## 🎯 قواعد ذهبية

### 1. قاعدة الدمج المبكر
> **"دمج مبكراً ودمج كثيراً"**

**لماذا؟**
- تقليل التضاربات
- سهولة الحل
- تكامل مستمر
- اكتشاف المشاكل مبكراً

### 2. قاعدة الفرع القصير
> **"الفروع يجب أن تعيش أياماً، لا أسابيع"**

**لماذا؟**
- تقليل التعقيد
- سهولة المراجعة
- دمج أسرع
- أقل تضاربات

### 3. قاعدة الحذف بعد الدمج
> **"كل فرع مدموج = فرع محذوف"**

**لماذا؟**
- تنظيم المستودع
- وضوح أكبر
- سهولة التنقل
- توفير المساحة

### 4. قاعدة التسمية الواضحة
> **"اسم الفرع يجب أن يوضح غرضه"**

**أمثلة جيدة:**
```
feature/add-user-authentication
bugfix/fix-login-error
hotfix/security-patch
release/v2.0.1
```

**أمثلة سيئة:**
```
test
my-branch
temp
fix
```

### 5. قاعدة المراجعة دائماً
> **"لا دمج بدون مراجعة"**

**لماذا؟**
- جودة أفضل
- اكتشاف الأخطاء
- تبادل المعرفة
- توثيق القرارات

1. **لا تدمج كود غير مختبر**

   ```bash
   # سيء ❌
   git merge --no-verify feature/conflicted
   ```

3. **لا تحذف فروع نشطة**
   ```bash
   # سيء ❌
   git push origin --delete feature/active-development
   ```

4. **لا تدمج مباشرة في main دون PR**
   ```bash
   # سيء ❌
   git checkout main
   git merge feature/my-feature
   git push
   ```

   ```bash
   # سيء ❌
   # فرع لم يُحدث منذ عام
   ```

## 🎓 أمثلة من الواقع

### مثال 1: دمج ميزة جديدة

**الموقف:**
- فرع `feature/user-profile` جاهز للدمج
- الكود مختبر ومراجع
- لا توجد تضاربات

**الإجراء:**
```bash
# 1. تحديث
git checkout feature/user-profile
git pull origin feature/user-profile
git merge main

# 2. اختبار نهائي
npm test

# 3. فتح PR
# على GitHub: New Pull Request

# 4. بعد الموافقة
# GitHub: Merge Pull Request
# GitHub: Delete branch (automatic)
```

**النتيجة:** ✅ ميزة مدموجة، فرع محذوف، تاريخ نظيف

### مثال 2: تنظيف فروع قديمة

**الموقف:**
- 15 فرع لم يُحدث منذ 6 أشهر
- معظمها مدموج أو ملغى
- يسبب فوضى في المستودع

**الإجراء:**
```bash
# 1. تحديد الفروع المدموجة
git branch -r --merged main | grep copilot

# 2. حذف كل فرع مدموج (بعد التأكد)
for branch in $(git branch -r --merged main | grep copilot); do
    branch_name=${branch#origin/}
    git push origin --delete $branch_name
done

# 3. تنظيف محلي
git fetch --prune
```

**النتيجة:** ✅ مستودع نظيف، سهل التنقل

### مثال 3: حل تضارب معقد

**الموقف:**
- فرع `feature/new-ui` به تضاربات كثيرة
- تغييرات في نفس الملفات مع main
- يحتاج دراسة

**الإجراء:**
```bash
# 1. تحليل التضاربات
git checkout feature/new-ui
git merge main --no-commit --no-ff

# 2. مراجعة الملفات المتضاربة
git diff --name-only --diff-filter=U

# 3. حل كل ملف بعناية
# استخدم أداة مرئية مثل:
# - VS Code
# - GitKraken
# - Meld

# 4. اختبار شامل بعد الحل
npm test
npm run e2e

# 5. إكمال الدمج
git commit -m "Resolve merge conflicts with main"

# 6. فتح PR
```

**النتيجة:** ✅ تضاربات محلولة بعناية، لا مشاكل
